Problems I've worked through

The situations identity teams actually face, what I did about each one, and where to see the work.

  • A fired employee can still get in

    Measured how long a terminated user kept cloud access: their old password still worked at 79 seconds. Made offboarding revoke sessions and force a sync, cutting the cloud disable lag from about 29 minutes to about 3.

    See the test

  • 300 new hires start on the same day

    Created 306 accounts in one run from an HR file, each with the right role groups, checked against an answer key written beforehand.

    See the test

  • A Domain Admin hidden in a nested group

    Built a review that follows group nesting. It found the path I planted, plus two problems I didn't plant.

    See the review

  • Admins hold Global Admin around the clock

    Removed standing admin access, including my own. Global Admin now needs MFA, a reason and a second person's approval, and expires after one hour.

    See the setup

  • An employee's account is compromised

    Rebuilt the timeline from the logs, confirmed one account was affected, and contained it in 11 minutes. Found that passing MFA marked the risk as resolved, and added an alert for it.

    See the response

  • A forgotten app can read the whole directory

    Inventoried every app and its credentials, found an owner-less app with Tier 0 rights, deleted the risky one, and moved reporting to a managed identity with no stored secret.

    See the inventory

  • Moving an app to a new identity provider could lock everyone out

    Found that AD usernames use a non-routable suffix, so every cloud username differs. Connected ServiceNow by employee ID instead, so nobody's identity changed in the migration.

    See the design

  • A retired federation server could still forge sign-ins

    Migrated ServiceNow off AD FS to Entra ID, then decommissioned AD FS end to end, including its signing-key container in AD and its revoked certificate.

    See the decommission

  • An app can't keep a secret, and sign-in codes get stolen

    Built an OIDC app with no client secret, using PKCE. Proved a stolen code is useless without the verifier, works only once, and is never issued to an unassigned user.

    See the tests

  • A stolen smart card should stop working right away

    Built certificate-only sign-in with certificates from my own CA, the lab version of CAC/PIV. Then revoked a certificate and showed Entra still accepted it 40 minutes later, and documented what has to go with revocation.

    See the test
